# Windows Release Pipeline Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Extend the `/release` skill so every release produces both a macOS DMG (existing) and a Windows NSIS installer (new), both attached to the same GitHub Release, with WinSparkle auto-update on Windows reading the same shared `docs/appcast.xml`.

**Architecture:** Local `/release` skill keeps building Mac as today and orchestrates Windows via a GitHub Actions workflow triggered by tag push. WinSparkle is integrated into `windows/runner/` and reads the shared appcast (filtered by per-item `sparkle:os` attribute). The skill waits on the Windows workflow via `gh run watch` before reporting done.

**Tech Stack:** Flutter Windows desktop, CMake `FetchContent` (WinSparkle 0.8.x), NSIS (`makensis`), GitHub Actions (`windows-latest` runner), `gh` CLI, Sparkle 2 (Mac) + WinSparkle (Windows).

**Spec:** [`docs/superpowers/specs/2026-05-13-windows-release-pipeline-design.md`](../specs/2026-05-13-windows-release-pipeline-design.md)

- [ ] **Step 2: Download WinSparkle release and compute SHA256 (for FetchContent integrity check)**

```bash

  https://github.com/vslavik/winsparkle/releases/download/v0.8.1/WinSparkle-0.8.1.zip

```

Capture the hex SHA256. You'll paste it into `URL_HASH SHA256=<hash>` below.

- [ ] **Step 3: Edit `windows/CMakeLists.txt`**

Add this block AFTER the existing `project(papersuitcase ...)` line and BEFORE `add_subdirectory("flutter")`:

```cmake
# WinSparkle for auto-update
include(FetchContent)
FetchContent_Declare(
  winsparkle
  URL https://github.com/vslavik/winsparkle/releases/download/v0.8.1/WinSparkle-0.8.1.zip
  URL_HASH SHA256=<paste-sha256-from-step-2>
)
FetchContent_MakeAvailable(winsparkle)

# Expose WinSparkle paths to subdirectories
set(WINSPARKLE_DIR "${winsparkle_SOURCE_DIR}" CACHE INTERNAL "")
set(WINSPARKLE_INCLUDE_DIR "${winsparkle_SOURCE_DIR}/include" CACHE INTERNAL "")
set(WINSPARKLE_LIB_DIR "${winsparkle_SOURCE_DIR}/x64/Release" CACHE INTERNAL "")
set(WINSPARKLE_DLL "${winsparkle_SOURCE_DIR}/x64/Release/WinSparkle.dll" CACHE INTERNAL "")
```

Replace `<paste-sha256-from-step-2>` with the actual hex string from Step 2.

- [ ] **Step 4: Edit `windows/runner/CMakeLists.txt` to link WinSparkle**

Find the line `add_executable(${BINARY_NAME} WIN32 ...)` (already exists). After the existing `target_link_libraries(...)` lines, add:

```cmake
target_include_directories(${BINARY_NAME} PRIVATE "${WINSPARKLE_INCLUDE_DIR}")
target_link_libraries(${BINARY_NAME} PRIVATE "${WINSPARKLE_LIB_DIR}/WinSparkle.lib")

# Copy WinSparkle.dll next to the built exe so the app finds it at runtime.
add_custom_command(TARGET ${BINARY_NAME} POST_BUILD
  COMMAND ${CMAKE_COMMAND} -E copy_if_different
    "${WINSPARKLE_DLL}"
    "$<TARGET_FILE_DIR:${BINARY_NAME}>/WinSparkle.dll"
)
```

- [ ] **Step 2: Write the NSIS script**

Write `installer/papersuitcase.nsi`:

```nsis
; PaperSuitcase NSIS installer
; Build with: makensis /DVERSION=1.2.3 installer\papersuitcase.nsi
; Reads VERSION from /D define on command line.

!ifndef VERSION
  !error "VERSION must be defined on the command line: makensis /DVERSION=X.Y.Z papersuitcase.nsi"
!endif

!define APP_NAME       "PaperSuitcase"
!define APP_DISPLAY    "Paper Suitcase"
!define PUBLISHER      "Paper Suitcase"
!define APP_EXE        "PaperSuitcase.exe"
!define BUILD_DIR      "..\build\windows\x64\runner\Release"
!define UNINST_KEY     "Software\Microsoft\Windows\CurrentVersion\Uninstall\${APP_NAME}"

Name "${APP_DISPLAY} ${VERSION}"
OutFile "..\PaperSuitcase-Windows-v${VERSION}-Setup.exe"
InstallDir "$PROGRAMFILES64\${APP_NAME}"
InstallDirRegKey HKLM "Software\${APP_NAME}" "InstallDir"
RequestExecutionLevel admin
SetCompressor /SOLID lzma
ShowInstDetails show
ShowUninstDetails show

!include "MUI2.nsh"

!define MUI_ICON "${BUILD_DIR}\${APP_EXE}"
!define MUI_UNICON "${BUILD_DIR}\${APP_EXE}"

!insertmacro MUI_PAGE_WELCOME
!insertmacro MUI_PAGE_DIRECTORY
!insertmacro MUI_PAGE_INSTFILES
!insertmacro MUI_PAGE_FINISH

!insertmacro MUI_UNPAGE_CONFIRM
!insertmacro MUI_UNPAGE_INSTFILES

!insertmacro MUI_LANGUAGE "English"

Section "Install" SecInstall
  SetOutPath "$INSTDIR"

  ; Copy the entire Flutter Windows release tree
  File /r "${BUILD_DIR}\*.*"

  ; Start Menu shortcut
  CreateDirectory "$SMPROGRAMS\${APP_DISPLAY}"
  CreateShortCut "$SMPROGRAMS\${APP_DISPLAY}\${APP_DISPLAY}.lnk" "$INSTDIR\${APP_EXE}"
  CreateShortCut "$SMPROGRAMS\${APP_DISPLAY}\Uninstall.lnk" "$INSTDIR\Uninstall.exe"

  ; Uninstaller
  WriteUninstaller "$INSTDIR\Uninstall.exe"
  WriteRegStr HKLM "Software\${APP_NAME}" "InstallDir" "$INSTDIR"
  WriteRegStr HKLM "${UNINST_KEY}" "DisplayName"     "${APP_DISPLAY}"
  WriteRegStr HKLM "${UNINST_KEY}" "DisplayVersion"  "${VERSION}"
  WriteRegStr HKLM "${UNINST_KEY}" "Publisher"       "${PUBLISHER}"
  WriteRegStr HKLM "${UNINST_KEY}" "DisplayIcon"     "$INSTDIR\${APP_EXE}"
  WriteRegStr HKLM "${UNINST_KEY}" "UninstallString" "$INSTDIR\Uninstall.exe"
  WriteRegDWORD HKLM "${UNINST_KEY}" "NoModify" 1
  WriteRegDWORD HKLM "${UNINST_KEY}" "NoRepair" 1
SectionEnd

Section "Uninstall"
  Delete "$SMPROGRAMS\${APP_DISPLAY}\${APP_DISPLAY}.lnk"
  Delete "$SMPROGRAMS\${APP_DISPLAY}\Uninstall.lnk"
  RMDir  "$SMPROGRAMS\${APP_DISPLAY}"

  RMDir /r "$INSTDIR"

  DeleteRegKey HKLM "${UNINST_KEY}"
  DeleteRegKey HKLM "Software\${APP_NAME}"
SectionEnd
```

After the existing `Upload installer artifact` step, add:

```yaml
      - name: Upload installer to GitHub Release
        if: startsWith(github.ref, 'refs/tags/v')
        shell: pwsh
        env:
          GH_TOKEN: ${{ github.token }}
        run: |
          $tag = $env:GITHUB_REF_NAME
          $file = Get-ChildItem -Filter "PaperSuitcase-Windows-*.exe" | Select-Object -First 1
          if (-not $file) { throw "No installer .exe found to upload" }
          echo "Uploading $($file.Name) to release $tag"
          gh release upload $tag $file.FullName --clobber
```

The `--clobber` flag means re-running this step replaces an existing asset of the same name (useful when re-triggering after a fix).

````markdown
Edit `docs/appcast.xml`. Each release writes TWO `<item>` entries — one for macOS, one for Windows.

- **Patch releases**: REPLACE the existing top pair of `<item>` entries (both Mac + Windows of the most recent patch in the same minor series). Do not accumulate multiple patches of the same minor.

**macOS item template** (signature/length come from step 6):

```xml
    <item>
      <title>Version VERSION (macOS)</title>
      <sparkle:os>macos</sparkle:os>
      <pubDate>PUB_DATE</pubDate>
      <sparkle:version>BUILD_NUMBER</sparkle:version>

      ]]></description>

      <sparkle:version>BUILD_NUMBER</sparkle:version>
````

## Self-review notes (verified by author)

- **Spec coverage:** All 7 brainstorming decisions and all components/files from the spec map to specific tasks. WinSparkle update signing is intentionally absent (per "skip for v1" decision).
- **Type/name consistency:** `WINSPARKLE_DLL` / `WINSPARKLE_LIB_DIR` cache variables defined in Task 3 are consumed in the same task's runner CMakeLists; the installer filename pattern `PaperSuitcase-Windows-v${VERSION}-Setup.exe` is consistent across Task 5 (NSIS), Task 7 (workflow upload), Task 9 (skill appcast template).
- **Known implementation risk:** WinSparkle 0.8+ may require a signed appcast item by default. If `win_sparkle_init()` rejects unsigned updates at runtime, an unscoped follow-up task is required: generate an EdDSA keypair, store private key as GitHub secret `WINSPARKLE_ED_PRIVATE_KEY`, sign the installer ZIP in CI, embed public key via `win_sparkle_set_dsa_pub_pem()`. This affects only the auto-update path — manual installer downloads still work.
